# 구매내역 자동 담기 · 직접 입혀보기 — 2026-10-07

로컬 적용 범위: `STYLE_STUDIO_LOCAL=1`인 API와 Vite DEV에서만 켠다. 서비스 색상, 기존 이미지·온보딩 WebP/지연 로딩, 승인한 바로 보기 동작은 변경하지 않는다.

구매내역 선택 후 `추출 후 옷장에 자동으로 담기`를 체크하면 썸네일 파일을 최대 4개씩 준비해 서버에 보낸다. 202 접수 완료 이후 클라이언트를 닫아도 서버가 기존 분류/추출/저장 함수를 실행한다. 접수 전에 닫으면 완료를 보장하지 않는다. 상세 값은 구매내역 상품명/브랜드/가격/재질/색상/구매처를 우선 사용한다. URL·사진 중복은 기존 비교 정책을 재사용한다. 성공·중복·실패를 각각 기록하며 일부 실패가 나머지를 중단하지 않는다. 옷장 목록은 작업 진행 또는 재방문 때 갱신하고 담긴 아이템을 기존 수정/삭제 기능으로 관리한다.

작업은 `backend/.local/closet-jobs.sqlite3`, 원본은 같은 폴더 `import-sources`에 저장한다. 접수 키로 중복 요청을 막고 처리 결과를 아이템마다 기록한다. 단일 서버의 작업 스레드가 처리하며 재시작 시 진행 중 작업을 다시 대기 상태로 돌려 남은 아이템을 이어간다. 성공 후 원본 파일은 지운다. 한 접수에 최대 100개, 사진 8MiB/총100MiB, 사용자당 활성 작업2개다. 외부 큐 서비스 비용은 없다. 로컬 서버/컴퓨터가 꺼진 동안 실행되지는 않는다. 배포 환경의 무료 호스트 수면, 디스크 휘발성, 다중 워커는 이 구현으로 해결했다고 주장하지 않는다. 상시 처리 배포에는 영속 큐/작업 저장소/워커가 필요하다.

진입은 `오늘 코디 → 직접 입혀보기`. 추천 설정 off 또는 빈 추천 상태에서도 열 수 있다. 옷장/저장한 리소스, 이름·브랜드 검색, 탭 또는 드래그(모바일 꾹 누른 뒤 세로 드래그), 같은 코어 종류 교체, 2~6개 조합, 자동 생성 on/off, 세 포즈, 결과 기록을 제공한다. 만들기 재료 이미지는 브라우저에서 읽어 JPEG/PNG/WebP 데이터로 전달하고, 서버가 생성용 PNG로 보관한다. 옷장 등록 없이 재료만 또는 옷장과 혼합해서 사용할 수 있다. 얼굴 사진·키·몸무게를 기존 개인화 착장 생성에 전달하고, 신체 수치만 있는 경우에도 개인화 체형 지시를 쓴다. 기존 바로 보기 전신이 있으면 최초 캐릭터로 표시하며 해당 전신을 수정/재생성하지 않는다.

생성은 별도 서버 작업이며 다른 착장을 다시 요청하면 새로운 생성 키를 사용한다. 룩북 저장은 실제 `outfits`에 저장하고 리소스 상품 정보는 `metadata.studio_items`로 함께 보존한다. 피드 공유는 기존 편집기로 연결해 꾸민 뒤 게시한다. 게시 버튼을 누르기 전 자동 공개는 없다.

초기 검증 모드는 `AI_TEST_MODE=1`: 기준 인물 이미지를 반환하므로 선택 옷 반영·새 포즈·신체 생성 품질을 확인한 결과가 아니다. UI에도 `테스트 이미지 · 선택한 옷 미반영`을 표시한다. 해당 테스트 모드의 이미지 생성은 $0 폴백이며 기존 분류 함수는 API 키가 있으면 과금될 수 있다. 이후 현재 로컬을 `AI_TEST_MODE=0`으로 전환했고 회색 티셔츠/검정 카고 슬랙스 실제 착장을 약19.6초에 생성·저장했다. 생성 결과와 선택 아이템이 재진입 시 복원된다. 테스트 인물 결과/룩북 레코드는 검증 후 제거했다. 사용자 크레딧 제한/차감 정책은 기존 비활성 설정을 변경하지 않았다.

## 직접 입혀보기 UX 정리 · 2026-10-07

오늘 코디 하단 진입으로 이동하고, 옷장 아이템이 없으면 진입 카드를 숨긴다. 화면은 기존 앱 우측 영역에 표시하며 PC 사이드 메뉴와 모바일 하단 탭을 유지한다. 별도 영문 스튜디오 제목을 제거하고 포즈 select 화살표 오른쪽 간격을 12px 확보했다.

선택은 조합만 변경한다. 자동 생성 타이머/스위치를 제거했다. 입혀보기 버튼 또는 캐릭터 영역에 드롭해야 POST가 발생하며, 선택된 카드/선택 칩을 끌면 전체 선택 조합을 함께 넘긴다. 화면 밖 드롭은 생성하지 않는다. 직접 착장과 기본 캐릭터 개인화는 별도 /dress 및 /character 작업이다. 얼굴/신체/퍼스널 컬러 선택은 계정 ID별 기기 저장으로 유지하며 개인화 off에서는 사진을 보내지 않는다. 기본 캐릭터 이미지를 생성 입력에도 사용해 다른 랜덤 인물로 바뀌지 않게 했다.

기본 남녀 캐릭터를 실제 generate_model_look_image + Flare high 경로로 미리 생성해 frontend/public/studio-assets/characters/default-m.png, default-f.png에 저장했다(17.2초/19.4초, 계정 과금·DB 업로드만 로컬 파일로 대체). 첫 방문은 이 파일을 즉시 표시하며 신규 생성하지 않는다. 기존 바로 보기 신체 이미지/마스크/캐시는 사용하거나 변경하지 않는다. 개인화 캐릭터는 가상 기본 옷을 선택 목록으로 복원하지 않아 다음 옷장 요청에 가상 ID가 섞이지 않는다.
