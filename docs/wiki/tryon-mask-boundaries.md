# 바로 보기 마스크는 옷 픽셀 밖으로 확장하지 않는다

## 2026-09-24 명시적 수정 요청 — 실패 판정·정면 자세

사용자가 투명화 누락, 팔 퍼센트에서 완료되는 현상, 한 줄 한국어 오류, 프사 기반 정면·동일 자세 재생성을 요청했다.
이에 따라 이번 변경에 한해 승인 체크포인트의 캐시를 `tryon22`로 갱신했다. 기존 `tryon21` 결과는 다음 이용 시 다시 생성한다.
카메라 cover·인물 contain·2:3 프레임과 색상 연결 영역 분리 방식은 유지한다.

코드에서 확인한 허점은 캐시가 실제 PNG 대신 URL 존재만 검사했던 점과 카메라 초기 모드가 불투명 원본이었던 점이다.
팔 퍼센트 정체의 실제 서버 로그는 확보하지 않았으므로 발생 원인을 단정하지 않는다.
이제 캐시 PNG 네 개를 읽어 검증하고 검증 단계를 표시한다. 옷의 일부만 뚫린 마스크도 거부한다.
클라이언트는 서버의 검증 성공 표시와 네 자산이 없으면 저장·완료 처리하지 않는다.
카메라 진입 시 전체 옷 투명화를 기본으로 켠다. 오류 원문을 그대로 내보내던 폴백을 한국어로 바꿨으며 기존 한 줄 표시를 유지한다.
프롬프트는 프사 정체성만 참고하고 정면 머리, 대칭 팔, 평행한 발, 균등한 체중 배분으로 다시 그리도록 구체화했다.
근거: `backend/app/main.py` `_tryon_assets_valid`, `_tryon_cached_assets_valid`, `_TRYON_BODY_PROMPT`, `live_tryon_body`;
`frontend/src/proto/09-app.jsx` `formatTryOnErr`, `makeTryOnBody`; `frontend/src/proto/10-tryon.jsx` `TryOnCameraOverlay`.

검증: 백엔드 마스크·캐시 회귀 테스트 14개, 프론트 테스트 10개, 프로덕션 빌드 통과.
실제 프사 생성, 정면 각도·옷 경계의 육안 확인, 휴대폰 카메라 및 배포는 수행하지 않았다.
자세 통일은 생성 지시이며 별도 자세 판정 모델로 검증하지 않는다. 색상 분리의 의미론적 한계도 그대로다.


2026-09-22, 캐시 `tryon21`.

## 사용자 승인 체크포인트 — 변경 보호

사용자가 라이브에서 확인하고 “휴 됐다. 이게 내가 원한대로”라고 승인했다.
또한 “다시는 여기서 다른 작업하다가 수정하지 않게 기록해놔. 체크포인트처럼”이라고 요청했다.
승인된 코드 기준은 `3d5eef0`이며 마스크 수정 `5ee257e`를 포함한다.
Git 태그: `checkpoint/tryon-approved-2026-09-22`.

이 기능에 대한 사용자의 명시적인 변경 요청 없이 다른 작업 중 동작을 바꾸지 않는다.
공통 CSS 정리, 이미지 처리 통합, 리팩터링, 캐시 갱신도 이 보호 범위를 우회하지 않는다.
전체 저장소를 체크포인트로 되돌리지 말고, 필요하면 해당 커밋의 관련 함수/스타일만 비교한다.
다른 기능의 변경과 사용자 작업 파일을 덮어쓰지 않는다. 적용 지침은 루트 `AGENTS.md`에 있다.

승인된 동작:
- 카메라 영상은 `cover`/가운데 정렬, 인물 PNG는 `contain`, 전신 프레임은 2:3.
- 상의·하의·전체는 해당 옷 경계 안에서 카메라가 보이고 목 아래·바짓단에 흰 띠가 없다.
- 얼굴·피부·신발·배경·다리 사이는 유지한다. 고정 다각형이나 세로 확장을 다시 넣지 않는다.
- 현재 캐릭터 생성 비율, 서버 마스크 검증, `tryon21` 캐시를 유지한다. 불필요하게 재생성하지 않는다.

아래 미검증 표기는 개발 당시 기록이다. 이후 라이브 결과는 위와 같이 사용자가 확인했다.


## 원인

`tryon20`은 색상 마스크에 고정 다각형을 합치고, 배경 판정을 무시하는 세로 확장을 적용했다.
기하 마스크의 배경 분기는 `continue`만 하고 이미 칠한 값을 지우지 않아 배경에도 구멍이 남았다.
단순 피부색 조건은 밝은 피부를 놓쳤다. 면적만 확인하는 검증은 이 잘못된 큰 구멍도 통과시켰다.
검증 후 상품컷용 `_polish_cutout_alpha`를 적용해 검증한 알파와 실제 저장한 알파도 달랐다.
근거: 수정 전 HEAD의 `backend/app/main.py:8046`, `:8093`, `:8198`, `:8449`.

## 변경

생성 계약인 검정 티·파란 청바지에서 가슴·양쪽 허벅지에 연결된 색 영역만 원본 해상도로 분리한다.
흰 옷처럼 배경과 구분할 수 없는 생성본에는 임의의 구멍을 만들지 않는다.
작고 완전히 둘러싸인 무채색 질감만 메우고, 경계는 안쪽으로만 페더링한다.
양쪽 바짓단이 떨어져 있어도 둘 다 유지한다. 피부·다리 사이·배경은 확장 대상이 아니다.
검증은 각 부위의 세로 커버리지, 옷 밖 투명화, 상·하의 중복, 전체 마스크 합집합을 확인한다.
검증을 통과한 PNG는 상품 누끼 보정을 거치지 않고 그대로 저장한다.
근거: `backend/app/main.py:7804` `_tryon_garment_mask`, `:7868` `_tryon_make_assets`, `:7895` `_tryon_assets_valid`.

브라우저의 별도 색상 누끼·바짓단 직사각형 확장 폴백도 제거했다. 부위별 서버 이미지가 없으면
카메라를 시작하지 않고 재생성을 안내한다. 진입 시 세 마스크가 모두 있어야 준비 완료로 본다.
근거: `frontend/src/proto/10-tryon.jsx:439`, `frontend/src/proto/04-screens-ab.jsx:1551`,
`frontend/src/proto/09-app.jsx:1307`.

캐시 버전을 서버·클라이언트 모두 `tryon21`로 변경했다. 기존 결과는 다음 생성 시 교체된다.
생성 프롬프트는 머리 꼭대기 6%, 턱 17%, 허리 44%, 가랑이 53%, 발바닥 94%로 통일했다.
기존 가랑이 62%·발끝 96%는 8등신 및 위아래 6% 여백 지시와 모순이었다.
근거: `backend/app/main.py:7943`, `:8089`, `frontend/src/proto/03-data.jsx:185`.

## 검증과 한계

마스크 테스트 12개 통과. 배경/피부 보존, 양쪽 다리 사이 보존, 잘못된 구멍 거부의 세 테스트는
수정 전 HEAD에서 모두 실패하는 것을 확인했다. 1024×1536 합성 도형의 상·하의 마스크는
독립적으로 그린 정답과 IoU 99.5% 초과, 옷 밖 투명화 0을 확인했다.
프론트 테스트 8개 및 프로덕션 빌드 통과. 별도 프로필 테스트 1개는 기존 HEAD에서도
저장 경로 문자열이 달라 실패하는 테스트이며 이번 변경과 무관하다.

실제 사용자의 새 전신 생성·모바일 카메라 검증과 배포는 아직 수행하지 않았다.
색상 기반 분리는 임의의 옷을 인식하는 의미론적 모델이 아니다. 지정한 검정·파랑 생성 계약에 의존한다.
100% 경계 정확도나 얼굴 비율 개선을 실제 생성본에서 보장한 것은 아니다.
흰 옷 등 계약을 어긴 생성본은 기존 최대 2회 생성 후 실패 처리 흐름을 따른다.

## 추가 원인: 투명 영역 뒤의 카메라 여백

2026-09-22 사용자 라이브 재검증에서 목 아래와 종아리에 수평 흰 띠가 남았다.
이는 PNG 마스크와 별개로 카메라 `<video>`의 `objectFit: contain`이 만든 여백이었다.
2:3 프레임에 3:2 영상이 들어가면 영상은 프레임 높이의 27.8%~72.2%만 채우며,
그 밖의 투명한 옷 영역에는 프레임 배경 `#F2F1EE`가 보인다. 제보 화면의 수평 경계와 일치한다.

영상만 `cover`, `objectPosition: center`로 바꿨다. 인물 PNG는 계속 `contain`이며,
마스크·캐시 버전 변경이나 전신 재생성은 필요 없다. 카메라와 프레임 비율이 다르면
영상의 가로 또는 세로 가장자리가 잘릴 수 있지만 인물과 옷 마스크는 변형하지 않는다.
근거: `frontend/src/proto/10-tryon.jsx:602`, `frontend/src/proto/proto.css:343`.

실제 영상 스타일을 읽어 Chromium에서 canvas captureStream 영상과 투명 프레임을 합성했다.
900×600, 1920×1080의 contain은 상단·하단 샘플이 배경 RGB(242,241,238)로 재현됐다.
cover는 같은 위치가 영상 RGB(20,200,90)로 바뀌며 옷 밖과 다리 사이 배경은 보존됐다.
600×900 세로 영상에서도 통과. 프론트 프로덕션 빌드 통과.
WebKit 실행 파일이 없어 Safari 엔진 및 실제 iPhone 카메라 검증은 수행하지 못했다.
