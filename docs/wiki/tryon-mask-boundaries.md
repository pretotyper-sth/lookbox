# 바로 보기 마스크는 옷 픽셀 밖으로 확장하지 않는다

2026-09-22, 캐시 `tryon21`.

## 원인

`tryon20`은 색상 마스크에 고정 다각형을 합치고, 배경 판정을 무시하는 세로 확장을 적용했다.
기하 마스크의 배경 분기는 `continue`만 하고 이미 칠한 값을 지우지 않아 배경에도 구멍이 남았다.
단순 피부색 조건은 밝은 피부를 놓쳤다. 면적만 확인하는 검증은 이 잘못된 큰 구멍도 통과시켰다.
검증 후 상품컷용 `_polish_cutout_alpha`를 적용해 검증한 알파와 실제 저장한 알파도 달랐다.
근거: 수정 전 HEAD의 `backend/app/main.py:8046`, `:8093`, `:8198`, `:8449`.

## 변경

생성 계약인 검정 티·파란 청바지에서 가슴·양쪽 허벅지에 연결된 색 영역만 원본 해상도로 분리한다.
흰 옷처럼 배경과 구분할 수 없는 생성본에는 임의의 구멍을 만들지 않는다.
작고 완전히 둘러싸인 무채색 질감만 메우고, 경계는 안쪽으로만 페더링한다.
양쪽 바짓단이 떨어져 있어도 둘 다 유지한다. 피부·다리 사이·배경은 확장 대상이 아니다.
검증은 각 부위의 세로 커버리지, 옷 밖 투명화, 상·하의 중복, 전체 마스크 합집합을 확인한다.
검증을 통과한 PNG는 상품 누끼 보정을 거치지 않고 그대로 저장한다.
근거: `backend/app/main.py:7804` `_tryon_garment_mask`, `:7868` `_tryon_make_assets`, `:7895` `_tryon_assets_valid`.

브라우저의 별도 색상 누끼·바짓단 직사각형 확장 폴백도 제거했다. 부위별 서버 이미지가 없으면
카메라를 시작하지 않고 재생성을 안내한다. 진입 시 세 마스크가 모두 있어야 준비 완료로 본다.
근거: `frontend/src/proto/10-tryon.jsx:439`, `frontend/src/proto/04-screens-ab.jsx:1551`,
`frontend/src/proto/09-app.jsx:1307`.

캐시 버전을 서버·클라이언트 모두 `tryon21`로 변경했다. 기존 결과는 다음 생성 시 교체된다.
생성 프롬프트는 머리 꼭대기 6%, 턱 17%, 허리 44%, 가랑이 53%, 발바닥 94%로 통일했다.
기존 가랑이 62%·발끝 96%는 8등신 및 위아래 6% 여백 지시와 모순이었다.
근거: `backend/app/main.py:7943`, `:8089`, `frontend/src/proto/03-data.jsx:185`.

## 검증과 한계

마스크 테스트 12개 통과. 배경/피부 보존, 양쪽 다리 사이 보존, 잘못된 구멍 거부의 세 테스트는
수정 전 HEAD에서 모두 실패하는 것을 확인했다. 1024×1536 합성 도형의 상·하의 마스크는
독립적으로 그린 정답과 IoU 99.5% 초과, 옷 밖 투명화 0을 확인했다.
프론트 테스트 8개 및 프로덕션 빌드 통과. 별도 프로필 테스트 1개는 기존 HEAD에서도
저장 경로 문자열이 달라 실패하는 테스트이며 이번 변경과 무관하다.

실제 사용자의 새 전신 생성·모바일 카메라 검증과 배포는 아직 수행하지 않았다.
색상 기반 분리는 임의의 옷을 인식하는 의미론적 모델이 아니다. 지정한 검정·파랑 생성 계약에 의존한다.
100% 경계 정확도나 얼굴 비율 개선을 실제 생성본에서 보장한 것은 아니다.
흰 옷 등 계약을 어긴 생성본은 기존 최대 2회 생성 후 실패 처리 흐름을 따른다.
