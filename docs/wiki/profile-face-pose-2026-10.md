# 프로필 얼굴과 촬영 각도 분리 — 2026-10-25

사용자는 비스듬한 프로필 사진을 적용하면 얼굴 각도와 자세가 복사되어 어색해지는 현상만 수정하고, 바로보기의 옷 경계·투명화·핏을 그대로 유지하며 즉시 롤백할 수 있게 요청했다.

## 변경

- `backend/app/main.py` `_personal_look_body_note`/`_model_look_prompt_with_reference`: Image 1은 얼굴 특징과 정체성만 제공한다. 셀카의 머리 yaw/roll/pitch, 촬영 시점, 올라간 어깨와 얼굴 옆 손은 복사하지 않고 얼굴·목·몸을 하나의 자연스러운 사진으로 다시 구성한다. 얼굴은 수평·준정면, 몸은 Image 2의 편안한 포즈를 참고한다. 얼굴 정면과 몸의 대칭 강직 자세를 구분한다. 키·몸무게 기반 체형 지시는 유지한다.
- `generate_model_look_image`: 실제 프로필 얼굴과 별도 스냅 참조가 있으면 스냅의 전신 포즈를 보존해 전달한다. 신체 수치만 개인화하는 동일 참조 경로는 기존 머리 crop을 유지한다. 일반 AI 착장 경로는 변경하지 않는다.
- `_TRYON_BODY_PROMPT`: 정체성 고정을 원본 사진의 기하학 고정과 구분한다. 덜 보이는 얼굴 특징은 일관되게 추론하고 새 정면 시점에서 다시 그리도록 지시한다. 머리카락 때문에 가려진 귀를 억지로 노출하도록 강요하지 않는다.
- 새 요청의 개인화 착장 캐시에 `personal-body2-facepose1`, 바로보기 생성 캐시에 `tryon22-…-facepose1`을 사용한다. 마스크 버전/기존 저장 URL/프런트 자산 버전은 유지하며 기존 결과를 삭제하거나 일괄 재생성하지 않는다. 수정은 새 생성 요청부터 적용된다.

## 보호 범위와 검증

바로보기의 POSE/FRAMING/OUTFIT 지침은 변경 전 문자열과 완전히 일치한다. `_tryon_make_assets`, 옷 마스크, 부드러운 경계, 마스크 검증, 캐시 자산 검증, 전경·배경 보정 및 프런트의 영상/PNG 표시 방식은 변경하지 않았다. `live_tryon_body` 실행 코드는 새 요청 캐시 키 접미사 외에 동일하다. AST 비교 결과 나머지 303개 함수가 동일하며 일반 AI 착장 프롬프트는 남/여/성별미지정×수치 유무 6개 비교에서 바이트 단위로 일치했다.

`test_model_look`, `test_look_reference_pipeline`, `test_tryon_body`, `test_live_coordinate_pipeline`: 68개 통과. 기존 테스트 하나가 `_apply_model_looks` 뒤의 다른 함수까지 검사해 실패하므로, 동일 검증을 해당 함수 AST 범위로 정확히 한정했다. 실제 사용자 얼굴을 이용한 새 생성/육안 품질 비교는 수행하지 않았다. 테스트는 요청 인자와 보호 동작을 검증하며 생성 모델의 최종 얼굴 유사도·포즈를 보장하지 않는다.
