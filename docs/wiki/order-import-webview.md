# order-import-webview

쇼핑몰 로그인은 모달 안 화면에서 한다. 무신사 통합 로그인은 `X-Frame-Options: DENY`라 일반 웹의 iframe으로 넣을 수 없다 (`member.one.musinsa.com/login`, 2026-09-06). 데스크톱 앱은 `desktop/` Electron 래퍼의 실제 `<webview>`를 쓰며 세션은 `persist:lookbox-orders` 파티션에 유지한다. 일반 브라우저의 로컬 개발판은 Playwright 화면 스트림을 대체 경로로 쓴다. 아이디·비밀번호는 Lookbox가 읽거나 저장하지 않는다.

흐름: 몰 칩 선택 → 「주문 내역 가져오기」 → 쇼핑몰 로그인 → 로그인되면 주문내역으로 자동 이동 → 「불러오기」로 상품 링크·이름·이미지·가격·구매일을 순서대로 추출 → 선택한 옷을 「N개 담기」 또는 「취소」 → URL 여러 개 추가와 같은 상세입력 화면에서 「담고 다음 옷 / 담고 완료」. Electron은 실제 로그인이 필요해 가운데 420px WebView와 PC 2열을 유지한다. 일반 웹의 Chrome 확장은 로그인 창을 별도 팝업에 띄우므로 두 번째 모달을 열지 않는다. 기존 아이템 추가 시트 안에서 「쇼핑몰 로그인 / 주문내역 열기 / 옷 가져오기」 3단계와 다음 CTA를 보여주고, 수집이 끝나면 같은 자리에서 상품 썸네일·구매처·가격·구매일 후보 목록으로 전환한다.

읽기 순서: Electron 네이티브 `<webview>` → 기존 네이티브 `window.LookboxNative.collectOrders` → Chrome 확장 `COLLECT` → localhost Playwright(`tools/order-collector/collect.mjs --embed`). 일반 웹은 확장이 520×760 로그인 팝업을 열고, 로그인 후 주문내역으로 재이동해 상품을 하나씩 Lookbox 모달로 보낸다. Lookbox 쪽은 기존 독립 구매내역 모달 대신 PC 2열 연결 시트를 유지한다. 왼쪽에는 진행 단계·CTA, 오른쪽에는 현재 Chrome 주소와 연결 상태를 보이며 실제 로그인은 열린 Chrome 팝업에서 한다. 수집 성공하거나 Lookbox 모달을 닫으면 팝업도 닫힌다. 구매내역 탭을 처음 열 때 확장 설치 상태를 한 번 확인한다. 없거나 구버전이면 기존 「쇼핑몰 로그인 → 주문내역 열기 → 옷 가져오기」 앞에 `0. 확장 프로그램 설치`만 둔다. Chrome·Edge는 `확장 프로그램 설치하기`가 각 스토어의 **확장 상세 페이지**를 열고, 그 페이지의 설치 버튼이 브라우저 권한 확인을 연다. 설치 페이지를 다녀와 원래 탭에 돌아온 때만 한 번 더 확인한다. Safari·그 밖의 데스크톱 브라우저는 구매내역 수집을 지원하지 않아 이유와 사진 등록 CTA를 보인다. Safari 지원은 별도의 Safari Web Extension·App Store 배포가 필요하다. 공개판의 스토어 주소는 `VITE_ORDER_EXTENSION_STORE_URL`·`VITE_ORDER_EDGE_EXTENSION_STORE_URL`로 설정한다. 기본 뷰포트는 모달 칸 크기·아이폰 UA다. 쿠팡 확장은 주문내역을 반환 주소로 직접 넣으면 Akamai `Access Denied`가 발생하므로, 쿠팡이 허용하는 홈 반환 로그인 주소로 인증한 뒤 주문내역으로 이동한다. Electron 경로는 쿠팡 홈 로그인 링크를 사용한다. 차단 문서는 주문내역 준비 완료로 처리하지 않는다.

일반 Chrome 웹앱은 쇼핑몰 HTML을 iframe으로 그대로 삽입할 수 없다. 쇼핑몰의 frame 차단과 브라우저 보안 경계 때문이다. 다만 로컬 웹앱은 Playwright의 화면 스트림과 클릭·키보드·스크롤 전달을 사용해 모달 안에서 실제 로그인·주문내역 확인을 지원한다. 이는 iframe이 아닌 로컬 브라우저 화면의 실시간 중계이며, 로그인 정보는 Lookbox가 읽거나 저장하지 않는다. 이 경로에서는 확장이 선택한 주문 썸네일을 파일로 전달할 때만 쓰인다. 배포 웹은 확장이 실제 주문내역에서 읽은 상품명·썸네일·브랜드·가격을 오른쪽 Chrome 영역에 즉시 채운다. 이 목록은 쇼핑몰 페이지 복제가 아니라 Lookbox가 표시하는 실제 추출 결과다.

실제 로그인 웹뷰는 Chrome 웹앱이 아니라 Electron 데스크톱 앱에서만 쓴다. 데스크톱은 `<webview partition="persist:lookbox-orders">`로 오른쪽에 쇼핑몰 로그인·주문내역을 직접 표시한다. 일반 Chrome은 같은 동작을 확장 탭과 추출 결과 목록으로 대체한다. 오른쪽 추출 목록은 자체 스크롤이며, 항목 보조 정보는 브랜드·가격·구매일 중 실제 읽힌 값만 ` · `로 잇는다. 값이 하나면 구분점을 표시하지 않는다.

Chrome 확장 경로는 로그인 직후 주문내역을 자동으로 읽어 오른쪽 목록을 채운다. 후보를 읽는 단계는 Chrome 확장과 쇼핑몰 사이의 통신이며 Lookbox의 AI·이미지 처리 API를 호출하지 않는다. 후보의 중복 확인은 비용 없는 API 조회다. 사용자가 상품을 확정해 옷장에 담을 때만 상품별 사진 등록·이미지 처리 API와 크레딧 차감이 발생한다.

쇼핑몰 로그인 쿠키가 남아 있으면 확장은 주문내역 탭을 비활성으로 열어 읽고 닫으므로 별도 창이 보이지 않는다. 로그인되지 않은 경우에만 그 탭을 앞으로 가져와 사용자가 로그인한다. 로그인 대기 중 「다른 쇼핑몰」을 고르면 진행 토큰을 즉시 무효화하고 열린 수집 탭을 취소하므로, 이전 쇼핑몰의 로그인 완료·자동 수집 콜백이 다음 화면을 열 수 없다. 주문내역 수집을 시작했거나 후보가 표시된 뒤에는 바깥 클릭으로 추가 시트를 닫지 않으며 ESC·X만 닫기 수단이다. 닫기 애니메이션에서는 상태 초기화를 280ms 뒤로 미뤄 2열이 함께 사라진다.

확장은 새 탭을 열기 전에 Chrome에 이미 열린 같은 쇼핑몰 탭을 최근 사용 순으로 찾는다. 해당 탭이 있으면 그 탭의 로그인 상태와 주문내역을 사용하고, 없을 때만 새 탭을 만든다 (`0.3.25`).

확장으로 수집한 상품은 서버가 상품 페이지를 다시 긁지 않는다. 확장이 로그인된 Chrome에서 주문내역 썸네일을 받고 사진 등록 API로 보내며, 상품명·구매처·가격·원본 상품 URL도 함께 저장한다. 따라서 무신사 등 서버의 상품 페이지 요청을 제한하는 쇼핑몰도 주문내역에서 이미 보인 이미지로 등록할 수 있다. 구매내역 후보·결과는 사진/URL 탭을 다녀와도 메모리에 유지한다. 상세 확인에서 입력 화면으로 뒤로 돌아오거나 「다른 쇼핑몰」을 누르면 완료된 수집 상태를 비우고 쇼핑몰 선택 화면을 복원한다. 모바일 웹은 「구매내역은 PC에서 불러올 수 있어요」 안내와 낮은 대비 CTA를 표시하고, CTA를 탭하면 PC 전용 토스트를 띄운다.

「이미지 불러오기가 제한되는 URL이에요」는 URL 탭의 서버 URL 읽기 경로에서만 보인다. 확장 구매내역 경로는 `FETCH_IMAGE`로 Chrome이 주문내역 썸네일을 data URL 파일로 넘기므로 이 문구로 폴백하면 안 된다. 이미지 전달은 확장 `0.3.0` 이상에서 지원한다. 이전 `0.2.x` 또는 비활성 확장은 구매내역 이미지 전달을 할 수 없다.

웹스토어 공개 전 UX 검수는 `?orderDemo=1`에서만 가짜 확장 모드를 쓴다. 「샘플 주문내역 보기」를 누르면 추가 시트가 PC 2열로 넓어지고, 왼쪽에는 연결 단계, 오른쪽에는 주소 표시줄을 포함한 가상 Chrome 로그인 화면이 열린다. 가상 로그인 버튼 → 「주문내역 열기」 → 「옷 가져오기」 순서로 직접 진행한다. 오른쪽 화면은 로그인 완료·쇼핑몰 주문내역·상품 읽기 상태로 바뀌며, 수집 중에는 찾은 옷 개수가 하나씩 늘어난다. 이후 「취소 / N개 담기」, 한 벌씩 상세입력, 완료 토스트까지 실제 흐름과 같지만 서버를 호출하거나 옷장에 저장하지 않는다. 개발 서버 기본값은 실제 확장 연결이므로, 공개판과 같은 흐름을 검증한다.

설치 전 흐름 미리보기는 개발 서버에서 기본으로 켜진다(배포판은 `?orderPreview=1`). 설치 CTA → 가상 Chrome 웹 스토어 상세 페이지 → 「Chrome에 추가」 → 브라우저 권한 확인의 「확장 프로그램 추가」까지 실제 순서를 그대로 보인다. 추가를 누르면 실제 설치 대신 같은 시트의 쇼핑몰 선택 및 가상 로그인 화면으로 이어진다. 가상 로그인 성공은 즉시 주문내역 URL로 이동해 「쇼핑몰 로그인」·「주문내역 열기」를 함께 완료 처리한다.

구현: `frontend/src/proto/order-import-session.jsx`, `04-screens-ab.jsx` `collectOrderItems`, `backend/app/main.py` `live_orders_collect`, `frontend/src/proto/09-app.jsx` `_order`·`_view` 스트림.

주문내역 URL은 사용자가 찾지 않는다. UI는 `frontend/src/proto/order-platforms.js` `ordersUrl`, 수집기는 `tools/order-collector/platforms.mjs`와 `extensions/lookbox-orders/platforms.js`의 `urls` 첫 주소. 몰이 경로를 바꾸면 세 파일을 같이 고친다. 수집 로직은 DOM 상품 링크를 줍지만, 첫 goto가 404면 빈 목록이 된다.

창을 못 열면 문구는 두 줄(`white-space: pre-line`). 휴대폰은 「이 기기에서는… / 컴퓨터에서 다시…」. PC(`wide`)는 「쇼핑몰 창을 열지 못했어요. / 이 컴퓨터에서 다시 열어 주세요.」 로컬 판정은 localhost뿐 아니라 `::1`·사설 IP도 수집기를 탄다.

2026-09-13 확인: 무신사 `/order/order-list`, 29CM `/order/my-order/list`, 지그재그 `/order-list`, W컨셉 `/MyPage/MyOrderList`, KREAM `/my/buying`, SSG `pay.ssg.com/myssg/orderList.ssg`, 머스트잇 `/m/mypage/order_list`은 현재 로그인 또는 주문 화면으로 이동한다. 더현대의 기존 두 경로는 404여서 지원 목록에서 제거했다. 네이버페이는 검증 환경의 네트워크 포털로 리디렉션돼 로그인 세션에서 별도 확인이 필요하다. 2026-09-11 브랜디는 로그인·주문 화면이 빈 페이지여서 지원 목록에서 제거했다.

네이버페이 결제내역은 일반 상품 링크가 아닌 결제 카드와 버튼형 페이지네이션이라 범용 링크 수집기를 쓰지 않는다. 확장 `0.3.18`은 카드에서 의류 키워드가 있는 상품명·이미지·가격·결제일을 읽고, 첫 페이지 후보를 RC에 즉시 보낸 뒤 페이지 버튼을 최대 60쪽까지 넘겨 새 후보만 추가한다. 카드에 상품 상세 링크가 없으면 판매처 로고 등 목록 썸네일만 사용할 수 있으며, 그 경우 상품 상세 사진을 보장하지 않는다.

지그재그는 가입 완료 뒤 주문 URL을 직접 열지 않고 `마이페이지 → 주문 배송` 메뉴를 클릭한다. 회원가입은 로그인 완료와 같은 경로로 감지하며, 메뉴를 못 찾았을 때는 `NEED_LOGIN` 같은 내부 상태를 노출하지 않고 「주문 배송 화면을 열지 못했어요. 다시 로그인해 주세요.」로 안내한다 (`extensions/lookbox-orders/background.js`, 확장 `0.3.19`).

지그재그 주문 배송 화면이 실제로 비어 있으면 확장은 그 탭을 그대로 둔 채 RC로 포커스를 돌리고 「아직 주문내역이 없어요. 첫 주문 후 다시 불러와 주세요.」라고 안내한다. 의류 후보가 없는 일반 수집 실패와 구분한다 (`0.3.20`).

에이블리 주문내역의 현재 주소는 `https://mobile.a-bly.com/orders`다. 회원가입 뒤 마이페이지 메뉴를 클릭하는 우회 대신 이 주소를 직접 연다 (`0.3.22`).

모든 쇼핑몰은 상품 후보를 읽기 전에 화면의 「주문내역 없음」 상태를 공통 판별한다. 실제 주문이 없으면 주문 탭은 열어 둔 채 RC로 돌아와 「주문내역에 담을 옷이 없어요. 첫 주문 후 다시 불러와 주세요.」로 통일한다 (`0.3.23`).

에이블리는 `주문·예약 내역` 화면에서 빈 주문을 「검색 결과가 없습니다.」와 배송중·배송완료 0으로 표시한다. 이 조합도 빈 주문으로 판별한다 (`0.3.24`).

W컨셉은 `MyPage/MyOrderList`의 조회 기간을 최대 12개월로 제한하지만 최근 5년 주문을 지원한다. 확장 `0.3.26`은 현재 기간과 이전 두 12개월 구간을 차례로 조회해 최대 3년의 상품 후보를 합친다. 메뉴 링크인 「카테고리」는 상품 후보에서 제외하며, 「주문하신 내역이 없습니다」는 빈 주문으로 처리한다.

KREAM은 완료된 구매만 `https://kream.co.kr/my/buying?tab=finished`에서 읽는다. 목록의 지연 로딩 이미지에는 `data-src`·`data-original`·`data-lazy-src`를 `src`보다 우선해 깨진 플레이스홀더 대신 원본 상품 이미지를 사용한다 (`0.3.27`).

SSG·쿠팡·네이버처럼 식품·생활·패션이 함께 판매되는 주문 화면은 상품명·브랜드에 의류·신발·가방·패션잡화 신호가 있을 때만 후보에 넣는다. 식품·생활용품·뷰티·서비스 결제는 수집 전에 제외한다. SSG는 패션 브랜드도 판매하므로 지원 목록에는 유지한다 (`0.3.28`).

## 머스트잇 구매내역 경로

머스트잇 주문내역 진입점은 `https://mustit.co.kr/m/mypage/my_buying`이다. 확장 프로그램, 로컬 수집기, 화면 설정이 같은 주소를 사용한다 (`0.3.29`).

## 유효 구매 건만 수집

모든 쇼핑몰의 공통 추출기는 주문 카드의 상태 문구에서 취소·반품·교환·환불의 완료·처리·접수 상태를 제외한다. 같은 상품 링크가 반복되면 목록 상단(최신)의 유효 구매 건을 유지한다 (`0.3.30`). 네이버페이는 애초에 구매확정·결제완료·배송완료 상태의 카드만 읽는다.

## 머스트잇 상품 이미지

머스트잇 주문 카드 상단에는 판매자·채팅 아이콘이, 상품 행에는 실제 상품 이미지가 함께 있어 범용 링크 추출을 쓰면 채팅 아이콘을 선택할 수 있다. 머스트잇은 `.card_product_info`의 상품명·브랜드·옵션·상품 이미지를 전용으로 읽고 주문 상세 경로를 식별자로 사용한다 (`0.3.31`).

## 가상 브라우저 표기

구매내역 연결 시트의 오른쪽 가상 브라우저는 macOS의 빨강·노랑·초록 창 제어점을 사용하지 않는다. 운영체제와 무관한 창 아이콘과 `브라우저` 표기로 Windows·macOS 사용자 모두에게 자연스럽게 보이게 한다.

`안전한 연결` 보조 표기는 제거하고, 상품 후보는 모든 쇼핑몰에서 브랜드와 제품명의 문자·숫자 정규화 값을 기준으로 한 번만 남긴다. 가격·사이즈·주문번호·주문 상세 URL이 달라도 목록 상단의 상품을 우선한다 (`0.3.32`).

## 무신사 최근 3년 조회

무신사는 주문내역의 `DateSelector` 시작·종료 날짜 입력을 현재일 기준 3년 전부터 오늘까지로 바꾸고 `검색하기`를 누른 뒤 수집한다 (`0.3.33`). 무신사는 이미 열려 있는 주문내역 탭이 있으면 그 탭을 재사용하고, 수집값은 주문 페이지 DOM에서 즉시 읽는다. W컨셉도 연도별 검색으로 최근 3년을 순회한다. 다른 쇼핑몰은 기간 UI를 확인한 경우에만 각 구조에 맞춰 추가한다.

쿠팡 주문목록은 `requestYear` 연도 필터를 지원한다. 현재 연도부터 직전 2개 연도까지 각 페이지를 차례로 열어 합치며, 페이지마다 읽은 비패션 품목과 중복 상품은 기존 공통 필터에서 제외한다 (`0.3.34`).

지그재그 주문·배송 화면은 기간 필터를 열어 `최대 5년`을 선택한 뒤 수집한다. 이미 최대 5년이 선택된 경우에는 다시 열지 않는다 (`0.3.35`).

오른쪽 Chrome 추출 목록은 macOS 오버레이 스크롤바가 사라지지 않도록 고정 트랙·최소 34px 썸·`scrollbar-gutter`를 사용한다. 목록 길이와 현재 위치를 항상 알 수 있다.

쇼핑몰별 빈 화면 문구가 달라 감지에 실패해도, RC의 후보가 0개면 최종 안내는 「주문내역에 담을 옷이 없어요. 첫 주문 후 다시 불러와 주세요.」로 통일한다. 주문 자체가 없거나 옷으로 분류된 항목이 없는 경우 모두에 맞는 문구다.

네이버페이 후보 목록 아래 안내는 「이미지 없는 옷은 담은 뒤 바꿀 수 있어요.」로 바꾼다. 결제 카드가 실제 상품 URL을 제공하지 않는 경우에는 목록 이미지 외의 상품 상세 이미지를 자동으로 찾을 수 없다.
# KREAM 완료 구매 목록 (0.3.38)

KREAM의 완료 구매 목록은 일반 상품 링크가 아닌 `/my/buying/<id>` 링크로 항목을 구성한다. 전용 추출기로 상품명·사이즈·상품 이미지·주문 시각을 읽으며, `취소완료`, 반품·교환·환불 및 `검수 불합격` 건은 제외한다. 크림 CDN의 외부 이미지 차단을 피하기 위해 확장이 상품 이미지를 데이터 URL로 전달하고, 원본 URL은 등록 단계에서 쓴다.

# 무신사 3년 기간 조회 (0.3.39)

무신사는 기본 주문 목록에서 기간 입력창이 닫혀 있다. 확장이 검색 입력창을 먼저 열고, 날짜 입력 두 개를 최근 3년으로 바꾼 뒤 `검색하기`를 실행한다.

# 주문 정보 정제 (0.3.40)

상품명·브랜드·사이즈·가격·구매일 외의 행동 버튼 문구(`스냅 보기`, `상세 보기`, `배송 조회`, `후기 작성` 등)는 수집과 표시 전에 제거한다.

# 취소·반품 주문 제외 (0.3.41)

공통 수집기는 상품 링크뿐 아니라 해당 상품의 상위 주문 행을 확인한다. 취소·반품·교환·환불, 결제 오류, 검수 불합격 및 판매 취소 상태가 있으면 수집 대상에서 제외한다.

# 주문 상태 판별 보강 (0.3.43)

주문 상태는 상품 카드와 분리돼 앞에 놓일 수 있다. 공통 수집기는 모든 일반 쇼핑몰에서 상품 링크 직전 주문 텍스트의 가장 가까운 상태를 읽어 취소·반품·교환·환불·결제오류·검수불합격·판매취소를 제외한다. 네이버페이·머스트잇·크림 전용 수집기도 같은 제외 규칙을 유지한다.

# 주문 상태 카드 범위 보정 (0.3.44)

페이지 전체에서 앞선 주문 상태를 참조하면 이후 정상 주문까지 빠질 수 있다. 일반 쇼핑몰은 이제 상품 카드 내부의 완료된 취소·반품·교환·환불·결제 오류·검수 불합격·판매 취소 상태만 제외한다.

# 주문 상태 인접 판별 (0.3.45)

상태와 상품 카드가 분리된 주문 페이지에서는 정확히 완료된 주문 상태만 읽고, 같은 열에서 상품 바로 위 360px 안에 있는 상태만 연결한다. 이전·다음 주문의 상태는 참조하지 않으므로 정상 주문을 함께 제외하지 않는다.
