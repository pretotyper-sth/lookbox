# 바로 보기는 계정 프사를 쓰고, 카메라는 모바일만

마이페이지 설정에는 `바로 보기 이미지` 행이 없다. AI 착장은 프로필이 아니라
성별만 맞춘 룩북 모델이다. 바로 보기는 조합 추천받기 시트의 탭에서 연다.

탭 미리보기는 계정 `prefs.avatar`다. 별도 업로드 칸(`tryOnLocal`)은 없다.
원형 `ProfileAvatar`를 누르면 마이페이지 프사와 같이 바뀐다. 얼굴을 바꾸면
`tryOnBody`/`tryOnFrame`/`tryOnAssets`를 비워 다음 바로 보기에서 전신을 다시 만든다.
프사는 기기 localStorage data URL이 아니라 스토리지 URL을 `prefs.avatar`에
붙여 계정에 따라다닌다([[profile-avatar]], 2026-08-30).

- **PC (`wide`)**: 원형 프사 + 「이 사진으로 옷을 바로 비춰 볼 수 있어요 · 모바일 전용」.
  카메라는 열지 않는다.
- **모바일, 프사 있음**: 바로 보기 탭에 들어가면 「프로필 사진으로 전신 바로보기 이미지 만들기」
  한 줄만 보인다(줄바꿈 없음). 탭만으로는 전신을 만들지 않는다. 칸이나 「바로 보기」를 눌러야
  생성한다. 이미 전신이 있으면 그 버튼을 눌러 착장(옷만)을 연다. 상의·하의·전체에서만
  `getUserMedia`로 후면 카메라를 켠다. 시트는 닫지 않아 끄면 같은 탭으로 돌아온다.
- **모바일, 프사 없음**: 사진·PC와 같은 212px 칸에 「프로필 사진 올리기」.

새 전신은 서버가 `body/top/bottom/full` 네 PNG를 만든다 (`main.py` `_tryon_make_assets`).
차콜 반팔·중청은 원본 해상도에서 시드 플러드로 가르고, 신발은 하의 구멍에서 뺀다.
카메라 오버레이는 이 URL을 쓰고, 구형/수동 사진만 `punchBody`로 폴백한다.
기본 화면은 **착장**(옷만, 카메라 없음). 상의·하의·전체를 누르면 그 구멍을 카메라에
겹친다. 같은 버튼을 다시 누르면 착장으로 돌아간다.
2:3 프레임에 카메라와 오버레이를 `contain`으로 같이 넣는다(2026-09-06).
후면 카메라만 쓴다. 전환 버튼은 없다(2026-08-30).
전신 생성은 `gpt-image-2` + `quality=high`, 캐시 `tryon6-`. 차콜 반팔·중청 데님·
흰 스니커즈, 머리·발 위아래 4% 여백. 얼굴은 프사 본인 실사. `POST /api/live/tryon/body`는 SSE로
프로필 확인 → 생성 → 경계 정리 → 저장 단계를 흘린다. 같은 얼굴 캐시는
월 한도보다 먼저 돌려주고, 신규 성공만 KST 월 2회. 사용자 크레딧 0.

`tryOnRev`가 `tryon6`가 아니면 다음 바로 보기에서 전신을 다시 만든다.

생성 중 스켈레톤은 프사와 같은 80px 원형이다. 텍스트와 떨어지도록 원형만 위로 10px 올린다
(`proto.css` `.lb-tryon-skel`, 2026-09-10). 진행 바 아래 「처음 한 번만 만들면 돼요」.
전신 요청은 앱(`09-app.jsx` `makeTryOnBody`)에 남아 탭을 바꾸거나 시트를 닫아도 끊지 않는다.
다시 바로 보기 탭이면 진행 중이거나 완성된 상태가 보인다. 시트를 떠난 뒤에 끝나면 카메라를
자동으로 열지 않는다.
실패는 이유를 구분해 두 줄로 보여 준다. 서버 `_TRYON_FAIL_MSG`와 프론트
`formatTryOnErr`가 같은 축약 문구를 쓴다. 상품 추출용 「옷이 또렷하게」는 쓰지 않는다.
시트는 `white-space: pre-line`이라 줄바꿈을 그대로 그린다.
PC 기본 폭(`wide`, 760px+)에서는 생성을 돌리지 않는다. Chrome 검사 모바일 모드는
`innerWidth`가 줄어 `wide`가 꺼지므로 전신 생성이 실제로 나간다.

패널 높이는 사진 탭과 같다(168 + 힌트 칸 44). 탭을 바꿔도 시트 높이가 뛰지 않게
오류도 칸 안에 둔다.
