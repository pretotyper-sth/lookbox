# 바로 보기는 계정 프사를 쓰고, 카메라는 모바일만

마이페이지 설정에는 `바로 보기 이미지` 행이 없다. AI 착장은 프로필이 아니라
성별만 맞춘 룩북 모델이다. 바로 보기는 조합 추천받기 시트의 탭에서 연다.

탭 미리보기는 계정 `prefs.avatar`다. 별도 업로드 칸(`tryOnLocal`)은 없다.
원형 `ProfileAvatar`를 누르면 마이페이지 프사와 같이 바뀐다. 얼굴을 바꾸면
`tryOnBody`/`tryOnFrame`/`tryOnAssets`를 비워 다음 바로 보기에서 전신을 다시 만든다.
프사는 기기 localStorage data URL이 아니라 스토리지 URL을 `prefs.avatar`에
붙여 계정에 따라다닌다([[profile-avatar]], 2026-08-30).

- **PC (`wide`)**: 원형 프사 + 「이 사진으로 옷을 바로 비춰 볼 수 있어요 · 모바일 전용」.
  카메라는 열지 않는다.
- **모바일, 프사 있음**: 바로 보기 탭에 들어가면 「아직 전신 이미지가 없어요. / 바로 보기 클릭 시 프로필 사진으로 이미지를 만들어요」
  두 줄로 보인다. 프사 원형은 생성 스켈레톤과 같은 카드 좌표, 텍스트는 생성 진행 제목과 같은 왼쪽 좌표에 둔다. 탭만으로는 전신을 만들지 않는다. 칸이나 「바로 보기」를 눌러야
  생성한다. 이미 전신이 있으면 그 버튼을 눌러 착장(옷만)을 연다. 상의·하의·전체에서만
  `getUserMedia`로 후면 카메라를 켠다. 시트는 닫지 않아 끄면 같은 탭으로 돌아온다.
- **모바일, 프사 없음**: 사진·PC와 같은 212px 칸에 「프로필 사진 올리기」.

새 전신은 서버가 `body/top/bottom/full` 네 PNG를 만든다 (`main.py` `_tryon_make_assets`).
검정 반팔·중청은 원본 해상도에서 시드 플러드로 가르고, 신발은 하의 구멍에서 뺀다.
카메라 오버레이는 이 URL을 쓰고, 구형/수동 사진만 `punchBody`로 폴백한다.
기본 화면은 **착장**(옷만, 카메라 없음). 상의·하의·전체를 누르면 그 구멍을 카메라에
겹친다. 같은 버튼을 다시 누르면 착장으로 돌아간다.
2:3 프레임에 카메라와 오버레이를 `contain`으로 같이 넣는다(2026-09-06).
후면 카메라만 쓴다. 전환 버튼은 없다(2026-08-30).
전신 생성은 `gpt-image-2` + `quality=high`, 캐시 `tryon10-`. 검정 반팔·중청 데님·
흰 스니커즈, 정면 포즈, 머리·발 위아래 6% 여백. 얼굴은 프사 본인 실사이며, 셀피가 기울어도
정면·수평 얼굴로만 만든다. 프로필 키·몸무게는 현실적인 성인 비율에서 아주 약하게 다리선이 길어 보이도록
참고할 뿐 체형을 과장하지 않는다. `POST /api/live/tryon/body`는 SSE로
프로필 확인 → 생성 → 경계 정리 → 저장 단계를 흘린다. 같은 얼굴 캐시는 한도보다 먼저 돌려준다. 신규 요청은
성공만 KST 월 2회. 실패는 월 한도에 넣지 않고 **그날 3회**면 멈춘다(`DAILY_FAIL_LIMITS`,
`tryon_body_fail`). 구멍이 약하면 생성을 한 번 더 하고, 그래도 안 되면 저장하지 않는다.
한 계정에서 동시에 두 번 돌리지 않는다. 사용자 크레딧 0.

`tryOnRev`가 `tryon10`이 아니면 다음 바로 보기에서 전신을 다시 만든다.

생성 전 프사는 생성 중 스켈레톤과 같은 72px 원형 좌표를 유지한다. 안내는 한 문장으로
줄이고 프사 아래 11px(`.lb-tryon-static-copy` top 101px)에 둔다. 프사·안내와 생성
스켈레톤·진행 문구는 모두 위로 올린 같은 좌표를 쓴다. 진행 문구는 안내와 같은 12px 보조색
가운데 정렬로 「상태 (퍼센트)」 한 줄만 보인다. 바로 보기의 생성 전
스테이지는 대상 선택 행이 사진·URL의 힌트 행보다 24px 큰 만큼 144px로 줄인다. 그래서
탭 전체는 사진·URL과 같은 높이고, 안내 아래의 불필요한 여백을 만들지 않는다.
생성 중 스켈레톤은 프사와 같은 72px 원형이다. 텍스트와 떨어지도록 원형만 위로 10px 올린다
(`proto.css` `.lb-tryon-skel`, 2026-09-10). 진행 바 아래 「좀만 기다려 주세요. 한 번만 하면 돼요」를 진행 상태와 같은 왼쪽 정렬로 보여 준다.
전신 요청은 앱(`09-app.jsx` `makeTryOnBody`)에 남아 탭을 바꾸거나 시트를 닫아도 끊지 않는다.
다시 바로 보기 탭이면 진행 중이거나 완성된 상태가 보인다. 시트를 떠난 뒤에 끝나면 카메라를
자동으로 열지 않는다.
실패는 이유를 구분해 두 줄로 보여 준다. 서버 `_TRYON_FAIL_MSG`와 프론트
`formatTryOnErr`가 같은 축약 문구를 쓴다. 상품 추출용 「옷이 또렷하게」는 쓰지 않는다.
92% 근처에서 멈춰 보이던 건 `tryon_segment`(78–92%) 뒤 마스크 검증이 약하면
두 번째 `images.edit`를 수행하는데, 진행률이 뒤로 가지 않도록 한 UI가 재시도 중에도
92%를 유지했기 때문이다. 재시도 전용 단계를 표시하고, 큰 결과는 축소 해상도에서
마스크를 만든 뒤 원본 크기로 복원하며 검증은 Pillow 연산으로 처리한다. 결과 PNG 4개
업로드도 병렬화한다. 구멍은 차콜/중청이 더 분명하게 나오게 프롬프트·시드를 맞추고,
두 번 다 약하면 저장하지 않고 실패로 남긴다 (`main.py` `live_tryon_body`, 2026-09-18).
