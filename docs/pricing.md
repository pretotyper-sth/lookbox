# 요금제와 크레딧

AI를 쓰는 작업에는 실제로 돈이 나간다. 사용자에게는 '크레딧' 한 단위로만 보여주고,
무거운 작업일수록 많이 깎는다. 기본값은 무료 등급이고, 매달 1일에 다시 채워진다.

## 작업별 크레딧과 실측 원가

| 작업 | 크레딧 | 실측 원가 | 비고 |
|---|---|---|---|
| URL·구매내역으로 옷 등록 | 1 | $0.006 | 쇼핑몰 상품컷은 로컬 컷아웃이라 이미지 생성비 0 |
| 사진으로 옷 등록 | 2 | $0.076 | 분류 $0.0055 + AI 추출 $0.07 |
| 옷 사진 다시 만들기 | 2 | $0.076 | 위와 같은 경로 |
| 코디 추천 (1회, 여러 벌) | 1 | $0.010 | gpt-4o 한 번에 여러 벌 |
| AI 착장 이미지 (1장) | 5 | $0.25 | 이미지 생성. 프로 전용 |
| 바로 보기 전신 이미지 | **매달 1회 무료**, 이후 5 | $0.25 | 카메라로 대보는 기능 자체는 API 호출이 없다. 준비용 전신 이미지 한 장만 AI로 그린다 |
| 중복 확인·구매내역 수집·검색·백필 | 0 | $0 | AI를 쓰지 않는다 |

크레딧당 원가는 가벼운 작업 $0.006, 무거운 작업 $0.05 수준이다.

## 요금제

세 단계로 나눠 봤자 실질 차이는 크레딧 수뿐이라 고르는 데 시간만 든다. 둘로 줄였다.
**기능은 무료에서도 전부 열려 있고**, 유일한 기능 차이는 AI 착장 이미지다.

| | 무료 | 프로 |
|---|---|---|
| 가격 | 0원 | 9,900원/월 |
| 매달 크레딧 | 60 | 400 |
| 사진으로 옷 등록 | 30벌 | 200벌 |
| 링크·구매내역으로 등록 | 60벌 | 400벌 |
| 코디 추천 | 60번 | 400번 |
| AI 착장 이미지 | ✗ | ✓ |
| 원가 상한(전부 소진 시) | $1.8 | $12 |
| 평균 사용 가정 원가 | $0.6 | $3 |

카드에 '크레딧 N개'만 적으면 얼마인지 감이 안 오므로, 그 크레딧으로 실제로 뭘 몇 번
할 수 있는지를 함께 적는다(`plan_perks()`가 CREDIT_COSTS에서 계산한다 — 단가를 바꾸면
문구도 같이 바뀐다).

무료 60개는 '옷장을 만들고 코디를 받아보는' 한 달이 끝까지 가도록 잡았다 —
링크로 30벌 담고(30) 추천 15회(15)면 45개다.

가격은 평균 사용을 기준으로 잡았고(등록은 초반에 몰리고 그 뒤엔 추천 위주),
크레딧 상한이 손실의 뚜껑 역할을 한다. 전부 소진하는 사용자가 늘면 크레딧 수를 조정한다.
예전 '베이직'(5,900원/250)은 목록에서 뺐지만, 쓰던 계정이 있을 수 있어 정의는 남겨 뒀다.

## 무료 사용자 1인당 우리 비용 (상한)

무료는 매달 60크레딧이다. 크레딧당 원가가 작업마다 달라서, '가장 비싼 작업만 반복'한
경우가 상한이 된다(환율 1,400원/$ 가정).

| 무료 사용자가 이렇게 쓰면 | 우리 비용 |
|---|---|
| 전신 이미지 1회(무료) + 사진으로 옷 30벌 | **$2.53 · 약 3,542원** ← 현실적 최대 |
| 전신 이미지 1회(무료) + 재생성 11회(55크레딧) | $3.00 · 약 4,200원 ← 이론상 최대 |
| 전신 이미지 1회 + 사진 15 · 링크 15 · 추천 15 | $1.63 · 약 2,282원 |
| 전신 이미지 1회 + 링크로 60벌 | $0.61 · 약 854원 |

**무료 1인당 월 최대 약 4,200원, 현실적으로는 1,000~2,500원.** 대부분은 60개를 다 쓰지
않으므로 실제 평균은 더 낮다. AI 착장 이미지(가장 비싼 반복 작업)는 무료에서 막혀 있다.

바로 보기는 기능 자체가 무료다 — 카메라·오버레이·부위 전환은 전부 기기에서 처리하고
API를 부르지 않는다. 준비용 전신 이미지만 매달 1회 무료로 그려 주고, 그 뒤 다시 만들 때만
크레딧을 받는다(프로필 사진을 바꾸지 않으면 캐시라 아예 다시 만들지 않는다).

여기에 고정비(Render·Supabase·Vercel)가 별도로 붙지만 사용자 수에 비례하지 않는다.
스토리지는 아이템 50벌 기준 1인당 약 15MB(원본 + 컷아웃 + 썸네일)다.

## 구현

- 저장소는 기존 `credit_ledger` 테이블 하나다(스키마 변경 없음).
  - `reason='grant'` `delta=+N` … 그 달 지급분 (`metadata.period='2026-08'`)
  - `reason='<작업>'` `delta=-N` … 사용
  - `reason='plan'` `delta=0` … 요금제 변경 (`metadata.plan`)
  - 잔액 = 합계, 요금제 = 마지막 `plan` 행(없으면 free)
- 월 지급은 배치가 아니라 **첫 조회 때 그 달 지급분이 없으면 넣는다**(idempotent).
- 검사는 작업 **전**(`ensure_credits`), 차감은 **성공 후**(`spend_credits`).
  실패한 요청에는 과금하지 않고, 중복으로 건너뛴 등록도 과금하지 않는다.
- 모자라면 402와 함께 무엇에 몇 개가 필요한지 한국어로 알려준다.
- 요금제 변경은 `POST /api/live/billing/plan` + `X-Admin-Token`. 결제 연동 전이라
  사용자가 스스로 올릴 수 없다(그럴 수 있으면 요금제가 아니다).

```bash
# 특정 계정을 프로로
curl -X POST https://<api>/api/live/billing/plan \
  -H "X-Admin-Token: $ADMIN_TOKEN" -H "Authorization: Bearer <아무 로그인 토큰>" \
  -H 'Content-Type: application/json' \
  -d '{"plan":"pro","user_email":"someone@example.com"}'
```

## 아직 안 한 것

- 결제(PG) 연동. 지금은 요금제 비교만 보여주고 "결제는 준비 중"이라고 말한다.
- 크레딧 추가 구매(팩), 연간 결제, 팀 요금제.
